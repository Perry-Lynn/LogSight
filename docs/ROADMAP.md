# LogSight 通用化实施计划

## 目标

把 LogSight 从“可用的远程日志查看 MVP”逐步提升为可公开发布、可长期运行、跨环境可解释的通用 SSH 日志工具。

当前产品边界先明确为：**桌面端跨平台，远程端优先支持 Linux/Unix；Windows 远程日志作为后续适配目标**。在没有能力检测和清晰提示之前，不把某个远程环境的失败伪装成普通路径错误。

## 阶段总览

| 阶段 | 主题 | 主要交付物 | 完成标准 |
| --- | --- | --- | --- |
| 第一阶段 | 可靠性与安全底座 | 远程环境探测、实时流重连、导入安全、钥匙串恢复说明 | 断线可重连；不支持的远程环境能明确提示；导入配置不会静默执行脚本或覆盖已有服务器；钥匙串恢复边界可操作 |
| 第二阶段 | 通用协议与日志格式 | SFTP/本地解析通道、JSON/自定义格式、时区和多行规则 | 核心历史查询不依赖远端 GNU 命令；常见文本和 JSON 日志可配置解析 |
| 第三阶段 | 发布与运维质量 | macOS/Linux 发布矩阵、签名、校验、自动更新、诊断包 | 用户能从 Release 安全安装、升级、校验和反馈问题 |
| 第四阶段 | 团队与规模化 | 配置模板、共享但不含密钥的配置、并发限制、审计和脱敏 | 适合团队使用，敏感信息和日志内容有明确的生命周期控制 |

## 第一阶段实施清单

### 1. 远程环境能力检测

- SSH 连接成功后检测远程系统、默认 Shell 以及 `tail/grep/awk/find/stat` 等能力。
- 对缺少必要命令的服务器给出明确提示，区分“SSH 可连接”和“当前日志模式可用”。
- 文档明确：当前日志流、历史查询和日志源探测以 Linux/Unix 远程端为第一支持目标。
- 后续将把命令依赖抽象成能力接口，逐步迁移到 SFTP 读取和本地解析。

### 2. 实时流可靠性

- 网络中断或远程 `tail` 进程退出时，自动按退避间隔重连。
- 重连期间向界面发送状态和次数，不把短暂网络抖动直接显示为最终失败。
- 用户主动停止后不得继续重连；达到上限后进入可重试的错误状态。
- 重连后的首个 `tail` 不重复回放初始回溯行，并提示断线期间可能存在遗漏。

### 3. 配置导入安全

- 导入服务器配置时不覆盖当前已有服务器，导入记录使用新的本地 ID。
- 导入配置中的自动脚本默认关闭并清空，避免打开日志时静默执行不可信命令。
- 无法用当前主密钥解密的凭据不保留失效密文，界面提示重新录入。
- 后续增加带用户自定义口令的加密备份格式，解决跨设备迁移凭据问题。

### 4. 钥匙串恢复边界

- 保留当前“恢复钥匙串 / 明确确认后重建本地密钥”的安全策略。
- 在 README 中明确：重建密钥不会恢复旧密码和私钥，服务器地址等非敏感配置可以保留。
- 后续提供加密备份和恢复向导；不把主密钥明文写回配置文件或导出文件。

## 验收方式

每个阶段都需要同时满足：

1. `npm run build` 通过。
2. `cargo fmt --manifest-path src-tauri/Cargo.toml --all -- --check` 通过。
3. `cargo test --manifest-path src-tauri/Cargo.toml` 通过。
4. 至少覆盖一次真实 SSH 场景，并记录远程系统、认证方式、日志格式和未验证边界。
5. Release 文档与实际可下载资产保持一致，不把“本地编译成功”写成“所有平台已验证”。

## 当前已知非阻塞项

- SSH Config、SSH Agent、MFA/OTP 尚未实现。
- Windows 远程服务器命令适配尚未实现。
- macOS Intel、Linux 的自动 Release 工作流尚未补齐。
- 依赖清单仍有宽版本范围，需要后续收紧并配合依赖审计。
